# Custom random maps

Three original scripts in `rms/`, generated by `tools/gen_rms.py` (edit the
generator, not the .rmv). Checked offline only (see "Not verified").

| file | slot it takes | idea |
|---|---|---|
| `rms/archipelago.rmv` | Caspian Sea | many small islands, 2-8 players, fish 18-28 per player, 3-5 gold + 1-2 stone + 3-4 forests + 2 berries per player island, extra islands carry more gold/stone, `TeamGrowth false` so every player has an own island |
| `rms/twin rivers.rmv` | Channels | big land map (Rivers-style `RiverLandFill`, 90 % land), 2-3 fords per player (`GenerateShallows`, width 2), 7-18 forests per player, gold ring 6-8 tiles and stone ring around every start, small team angle so teams sit side by side on opposite sides |
| `rms/uplands.rmv` | Peloponnese | no water (`WaterlessMap`), high `HeightMapChaos` plateaus (choke points between them), 3 gold + 2 stone + 3 forests per player, many gold/stone neutral lands, for long games |

The task called the third map "Highlands". The game already has a "Highlands",
and the exe keys scripts by name, so it is named **Uplands**.

## How the game registers random maps (facts from `RiseAndFall.exe`)

* Scenario maps (`Data\map scripts\*.rmv`) are found by scanning (`*.rmv`,
  `Map Scripts\` strings at file 0x891fa0 / 0x891fa8).
* **Random maps are NOT scanned.** The exe holds a fixed table of 13 names
  (pointer array at VA 0xD26A00: Caspian Sea, Channels, Coastal, Continental,
  Highlands, Large Islands, Mediterranean, Oceania, Peloponnese, Plains,
  Rivers, Small Islands, Team Islands; the strings are at file offset
  0x891EA8-0x891F3B). The count function (VA 0xBC68F0) returns 13, the name
  getter is VA 0xBC6910. A second table of 5 names (VA 0xD26A34: Coastal,
  Continental, Mediterranean, Plains, Rivers) is the "Tourney" set, count at
  VA 0xBC6900. "Random" picks an index 0-12 (code at VA 0x6E606A-0x6E6082).
  A new `.rmv` dropped into the folder therefore does not show up by itself.
* The 13 shipped file names are exactly these names in lower case
  (`caspian sea.rmv` ...). So most likely: script file = table name + `.rmv` in
  `Data\random map scripts\`.
* The parser (keywords, `#if` functions) lives in `Default.dll`, which also
  holds the `.rmv` extension string. `StringTableID` / `StringHelpID` in the
  scripts point at unrelated Language.dll strings (e.g. 27009 is "(4) Karyer"),
  so they are leftovers. Our scripts reuse the IDs of the slot they replace.
* Displayed Russian names are Language.dll strings 34800-34812, in table order
  (likely: index 0 = 34800 "Kaspiyskoe more" ...). They do not change with
  the script content.
* Preview video: `Data\movies\Random Map Default.bik` is the fallback; the
  code at VA 0xBC7B85 builds `Movies\<name>.bik` and falls back to it.
  No video is needed for new maps (from the code, not seen running).
* Includes are relative to `Data\random map scripts\`, `.rmv` is appended
  (`#include "Common\Map Climate"`). Our scripts only include the shipped
  `Common\*` files, they have no sub folder.

## Install (for the patcher)

All players of a multiplayer game must have identical script files (and the
same exe patch in mode B), otherwise the generated maps differ and the game
desyncs.

### Mode A: replace a slot (no exe change, recommended first)

Copy into `<install>\Data\random map scripts\`, overwriting:

```
rms\archipelago.rmv   ->  caspian sea.rmv
rms\twin rivers.rmv   ->  channels.rmv
rms\uplands.rmv       ->  peloponnese.rmv
```

Back up the three originals first. The lobby keeps showing the old Russian
names (Caspian Sea, Channels, the Peloponnese slot) but generates our maps.
The unused sub folders (`caspian sea\` ...) stay untouched and are not read.
The slots chosen are not in the Tourney set and not the most used maps.

### Mode B: also rename the slots (small exe patch)

Overwrite the table strings in `RiseAndFall.exe` in place. Each slot is 12
bytes including the terminating NUL, the new names fit exactly:

| file offset | old | new |
|---|---|---|
| 0x891F30 | `Caspian Sea\0` | `Archipelago\0` |
| 0x891F24 | `Channels\0\0\0\0` | `Twin Rivers\0` |
| 0x891ED0 | `Peloponnese\0` | `Uplands\0\0\0\0\0` |

Then copy the files under their own names (`archipelago.rmv`,
`twin rivers.rmv`, `uplands.rmv`) and delete or keep the three old files.
The Russian display strings (Language.dll 34800, 34801, 34808) would still be
the old ones; changing them needs a resource edit of Language.dll (not done
here). If the file lookup is not name based as inferred, use mode A.

## Checks that can run offline

`python tools/check_rms.py` regenerates the maps into a temp folder and compares
byte for byte, runs the linter self-test, lints all 87 shipped scripts and the
three new ones. `tools/lint_rms.py` simulates the preprocessor for every map
size x 2-8 players x 3 start epochs x 2 climates x both PERCENT outcomes
(420 runs per script) and checks identifiers against the shipped vocabulary,
statement keywords against `Default.dll`, includes, balance, k-constants
defined on every path, same attribute set in every combination, and numeric
values against the range seen in shipped scripts. Quirks of shipped files
(stray `)`, unclosed `#if`, `(#define name value)` without comma, one undefined
`k` name) are reported as WARN there and as ISSUE in our scripts.

## Not verified (needs the game)

1. That the lobby/random pick really loads `<slot>.rmv` and our map appears
   (mode A) or that the renamed table works (mode B).
2. That the generator accepts the scripts: nested `#if IsXMap` blocks inside a
   player-count chain, `PlayerInnerRadius 0.7` / `PlayerOuterRadius 0.85` (a
   narrow ring instead of the shipped wide ring, for similar start distance),
   all values stay inside the shipped numeric ranges.
3. Fairness: per-player resource counts are identical by construction; start
   positions are only as symmetric as the engine's ring placement. Neutral
   lands are random.
4. "Enough wood/gold for the next age": counts per player are at or above the
   shipped island maps, but the amount per deposit and the age costs were not
   read, so this is not proven.
5. Twin Rivers: the number and course of rivers is decided by the generator
   (no keyword sets a river count). Two rivers and team sides are the intent,
   not a guarantee.
6. Uplands: choke points come from elevation noise and neutral plateaus, not
   from placed walls.
